## Course material and up-to-date docs

The lecture decks and reading sheets are PDFs outside the repo, at `~/ibt-college-learning-materials/M0N/dayNN/` (Module 3's Day 37 folder is spelled `Day37`). Extract them with `pdftotext -layout <file>.pdf -`. They define *what* each day builds and in what order.

Don't treat the material as the final word on APIs. The course PDFs can lag behind the versions installed here (React 19, Vite 8, Next.js 16), so check behaviour against the current official docs (react.dev, nextjs.org/docs, vite.dev, docs.python.org, MDN), and point out where the material is outdated. Known case: the material teaches `Component.propTypes` and says to watch for console warnings, but React 19 removed propTypes checking. The checks are silently ignored, and `defaultProps` on function components is gone too (use default values in the destructured parameters instead).

For Next.js projects, each project's `AGENTS.md` (generated by `next dev`) says to read the guides bundled in that project's `node_modules/next/dist/docs/` before writing Next.js code, because the installed version may differ from what you know.

## How the user wants to work

The user is a student and wants to understand what they're building, not just copy it:

- Explain a concept before asking them to implement it, in your own words, tied to the material.
- Give one implementation step at a time, with the exact file path and code.
- Check understanding with a question or small exercise after each meaningful step.
- Wait for the user to say "next" or "continue" before moving on. Don't skip material or bundle steps together.

## Commands

Every JS project is self-contained, with its own `package.json` and `node_modules`. Run commands from inside that project's folder (for example `M03-react-nextjs/day42/addis-eats`), never from the repo root.

```bash
npm install
npm run dev        # Vite dev server, or `next dev` for Next.js projects
npm run build      # Vite build to dist/, or `next build`
npm run lint       # ESLint
npm run preview    # Vite projects: serve the build
npm start          # Next.js projects: serve the build
```

There are no automated test suites. Changes are verified in the browser and its console. Next.js projects that need secrets ship a `.env.example`; copy it to `.env.local` (git-ignored). Python work (Module 1) is plain scripts run with `python <file>.py`, with no dependencies. Module 2 pages are static HTML/CSS/JS opened in a browser (VS Code Live Server); use relative asset paths so they work no matter which folder is served.

## Conventions

- Commit messages: `Add day NN: <topic>`, one commit per day or per clear stage within a day.
- Later Addis Eats days document their design decisions in Markdown files next to the code (`STRATEGY.md`, `BOUNDARY.md`, `DATA.md`, `AUTH.md`) and a README per day. Read them before changing a later-day snapshot, and extend them when adding to one.
